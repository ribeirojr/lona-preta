# Text and languages (I18N)

The game has exactly two languages, and **the mode decides the language**:

- **Night** mode shows **English** (`en`).
- **Modo Bandeira** shows **Brazilian Portuguese** (`pt`, document `lang="pt-BR"`).

All player-visible text lives in one object, `I18N`, in section 2 of the script, between the markers
`/* i18n:begin */` and `/* i18n:end */`. Do not remove or rename those markers: `scripts/check.mjs` reads them.

## Using text in code

```js
tr("act.clear")                              // "Clear the scrub" / "Limpar o mato"
tr("act.plant",{crop:"Milho"})               // "Plant Milho" / "Plantar Milho"
tr("case.hearing",{n:months})                // plural, see below
```

`tr(key, vars)` looks up the key in the current language and replaces `{name}` placeholders with `vars.name`.
If a key is missing it falls back to English, and if it is missing everywhere it returns the key itself,
so a visible `some.key` on screen means a typo.

## Adding a new string (checklist)

1. Pick a key: `group.name` in lower camel case. Reuse the group prefixes: `act.` actions, `case.` court case,
   `map.` map, `store.` stores, `shop.`, `market.`, `choose.`, `move.`, `end.`, `info.`, `log.` camp-log entries,
   `ev.` random events, `howto.`, `stat.`, `land.`, `theme.`.
2. Add it to **`en`** and **`pt`**, next to related keys. Keep them in the same order.
3. Use it: `tr("group.name",{...})`.
4. Run `node scripts/check.mjs`. It fails if the two languages disagree.
5. Look at a screenshot in both modes (long Portuguese text can wrap differently).

## Rules

- **Same placeholders** in both languages: `{n}` in `en` means `{n}` in `pt` (names must match).
- **HTML only `<b>` and `<em>`**, with no attributes and no double quotes inside the text.
- Strings are normal JS double-quoted strings. Escape nothing special; do not use backticks or `${}`.
- Do not translate place names (`Fazenda Santa Rita`, `Pontal do Paranapanema, SP`), crop names
  (`Feijão`, `Milho`, `Mandioca`) or the word `feira`. They are Portuguese in both languages on purpose.
  English gets short glosses via `crop.<name>.gloss` (for example ` (beans)`); Portuguese uses `""`.
- Currency is always `R$`. Write it as `R$30` in a literal or `R${c}` with a placeholder.
- Tone: plain and direct. Portuguese uses informal-neutral Brazilian ("você"), not European Portuguese.
  Use "lote" for plot, "fazenda" for estate, "acampamento" for camp, "assentamento" for settlement,
  "despejo" for eviction, "reintegração de posse" for repossession.

## Plurals

If you call `tr("key",{n})`, and `n === 1`, and a key named `key_1` exists, that one is used.
So define both **in both languages**:

```js
"ev.fox":"A fox got into the henhouse. Lost {n} hens.",
"ev.fox_1":"A fox got into the henhouse. Lost 1 hen.",
```

`check.mjs` fails if a `_1` key has no base key. Only the singular needs `_1`; everything else uses the base key.

## The camp log

Never log text. Log a key and its variables:

```js
log("log.harvest",{n:12,crop:"Feijão"});
```

The entry is stored as `{k,v,at}` and translated each time the log is drawn, so switching mode re-translates
the whole history. `at` is the month number; the date label ("Oct 2026" / "Out 2026") is also built at draw time.
For `log("log.bought",{item:"hen"})` the `item` is translated through `shop.<item>` when drawn.

## Dynamic keys

Some keys are built from data: `month.0`..`month.11`, `shop.<id>` and `shop.<id>.note`, `crop.<id>.gloss`,
`howto.1`..`howto.6`. If you add a shop item or crop you must add its keys in both languages
(see [RECIPES.md](RECIPES.md)).

## Switching mode

`toggleTheme()` flips the mode, saves it, calls `render()` and, if a modal is open, rebuilds it from `curModal`.
The first visit uses `?theme=night|bandeira` from the URL if present, then the saved choice, then the
operating system's light/dark preference (light gives Modo Bandeira).

## What the checker verifies

`node scripts/check.mjs` fails when: a key exists in only one language, placeholders or HTML tags differ,
a `_1` key has no base key, or the code refers to a key that does not exist. It warns about unused keys.
